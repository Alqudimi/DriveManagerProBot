# مدير Google Drive عبر Telegram

مشروع Python قابل للتثبيت يدير ملفات Google Drive عبر واجهة Telegram عربية. يعمل الوصول إلى الملفات من خلال Google Drive Mount في Colab؛ لا يحتاج Google API Key أو Service Account. ويستخدم بوت Telegram عنوان Local Bot API Server محليًا بصورة صريحة دون fallback إلى `api.telegram.org`.

> يدعم الإصدار الحالي تنزيل ملف من Drive وإرساله إلى محادثة البوت، وإعادة التسمية عبر `/mv`، والنقل والنسخ والحذف بعد التأكيد، وإنشاء المجلدات والتصفح والبحث ورفع المستندات وفهرسة CSV. إدارة صلاحيات المشاركة ليست ضمن هذا الإصدار. التشغيل الفعلي مع Colab وTelegram يتطلب إعداد المستخدم واختبارًا على حسابه.

## المتطلبات والتثبيت

يتطلب Python 3.10–3.13، و`uv`. لتجهيز Colab، حمّل ملف ZIP المرفق إلى جهازك وافتح Notebook في Colab. يبدأ الدفتر بربط Drive عبر `from google.colab import drive` (هذه هي الوحدة الرسمية في Colab، وليست `google.drive`). إذا لم يجد مجلد المشروع في `MyDrive`، يطلب منك رفع ZIP ثم يتحقق من مساراته قبل استخراجه. بعد ذلك شغّل الخلايا بالتتابع. يدير `uv` الاعتماديات باستخدام `pyproject.toml` و`uv.lock`:

```bash
uv sync --all-extras
uv run pytest
uv run ruff check .
```

الأرشيف المرفق يتضمن `.local/bin/telegram-bot-api` مبنيًا من المصدر الرسمي، لذلك يحاول `install-colab.sh` تشغيل `--help` ويعيد استخدامه دون طلب CMake أو إعادة بناء. إذا غاب الملف أو لم يعمل على النظام، يبني السكربت من مستودع Telegram الرسمي ويتحقق من عنوان `origin` وصلاحية الملف الناتج قبل تثبيته؛ يتطلب ذلك `git`, `cmake`, ومترجم C++ وOpenSSL/zlib/gperf ويستهلك وقتًا ومساحة. binary المرفق x86-64 ويحتاج GLIBC 2.38 أو أحدث، وهو متوافق مع صور Colab Ubuntu 24.04 المنشورة حاليًا حسب [ملاحظات إصدار Colab](https://colab.research.google.com/notebooks/relnotes.ipynb). صور Colab الأقدم مثل Ubuntu 22.04 قد لا تشغله؛ عندها اختر runtime أحدث أو أعد البناء في البيئة المستهدفة. لا ينزّل السكربت binary من مصدر مجهول.

## إعداد Telegram

أنشئ بوتًا عبر [@BotFather](https://t.me/BotFather) وخذ `BOT_TOKEN`. خذ `TELEGRAM_API_ID` و`TELEGRAM_API_HASH` من [my.telegram.org](https://my.telegram.org)؛ هذه بيانات تطبيق Telegram المطلوبة لخادم Bot API، وليست بيانات Google. انسخ `.env.example` إلى `.env` وأدخل القيم محليًا أو استعمل Colab Secrets. لا ترفع `.env` إلى Git.

أضف Telegram numeric user ID إلى `ADMIN_IDS` (قائمة مفصولة بفواصل). القيمة الفارغة تعني عدم منح أي مستخدم صلاحية. احرص على عدم مشاركة أسرارك أو سجل الخادم.

## Google Drive في Colab

اربط Drive تفاعليًا داخل جلسة Colab:

```python
from google.colab import drive
drive.mount('/content/drive')
```

ثم تحقق من وجود `DRIVE_ROOT` (افتراضيًا `/content/drive/MyDrive`). يمكن إضافة جذور أخرى مرئية فعليًا للحساب في `DRIVE_SHARED_DRIVE_ROOTS` مفصولة بفواصل. المسارات تمر بفحص containment قبل التعامل معها. قد تختلف طريقة ظهور Shared Drives وفق الحساب.

## Local Telegram Bot API

مصدر الخادم الرسمي: [tdlib/telegram-bot-api](https://github.com/tdlib/telegram-bot-api). شغّله بوضع `--local` على loopback فقط. في هذا الوضع يدعم Telegram تنزيلًا بلا حد حجمي ثابت، ورفعًا يصل إلى 2000 MB، ويعيد المسار المطلق المحلي لملفات `getFile` عندما يتوفر. هذه حدود واجهة Telegram وليست ضمانًا لإمكانية ملف بهذا الحجم في جلسة Colab؛ المساحة المتاحة، سرعة Drive، الشبكة وحصة الحساب عوامل حاكمة.

عند نقل بوت مستخدم سابقًا من الخادم السحابي إلى خادم محلي، يذكر Telegram ضرورة `logOut` لإلغاء تسجيله من الخادم الرسمي قبل الانتقال. لا ينفذ المشروع ذلك تلقائيًا؛ استخدمه مرة واحدة فقط عند الانتقال، وبعد فهم أثره على تحديثات البوت. راجع [تعليمات Telegram الرسمية](https://github.com/tdlib/telegram-bot-api#moving-a-bot-to-a-local-server). فشل الخادم المحلي خطأ صريح ولا يتسبب في التحول الصامت إلى السحابي.

## التشغيل والإيقاف

```bash
bash install-colab.sh
bash healthcheck.sh
bash run.sh
bash stop.sh
bash restart.sh
```

شغّل الأوامر من مجلد المشروع بعد توصيل Drive وإعداد `.env` أو تمرير الأسرار في بيئة runtime. `run.sh` يتحقق عبر استدعاء `getMe` من واجهة API المحلية قبل تشغيل polling، ثم يشغل البوت بالخلفية ويحفظ PID وسجل البوت في `state/bot.pid` و`state/bot.log`. يحفظ الخادم المحلي سجله في `state/bot-api.log`. `healthcheck.sh` يتحقق من Drive وAPI والمساحة ويحافظ على قيم الأسرار الموجودة في بيئة Colab بدل استبدالها بقيم `.env`. لا تقتل إلا PID المسجل للمشروع، ولا تنشر السجلات قبل مراجعتها.

## الاستخدام والقيود الحالية

الأوامر والمسارات النسبية تبدأ من `DRIVE_ROOT`:

```text
/browse [مجلد نسبي] [رقم الصفحة]       # واجهة الأزرار تعرض 15 عنصرًا للصفحة
/search كلمة
/download                              # اختيار عدة ملفات من المتصفح
/download_done                         # إرسال الملفات المحددة بالتتابع
/cancel_download                       # إلغاء قائمة الاختيار
/download "مسار ملف أو مجلد"
/mv "مسار العنصر" "الاسم الجديد"
/move "مسار المصدر" "مجلد الوجهة"
/cp "مسار الملف" "مجلد الوجهة"
/rm "مسار الملف أو المجلد الفارغ"  # يتطلب تأكيدًا بزر
/mkdir "اسم المجلد"
/index [مجلد]
/index_sync [مجلد]                     # فهرسة مباشرة غير مدمرة للمجلد
/find كلمة                           # يبحث داخل ملفات CSV
/info "مسار الملف"                  # الحجم والتاريخ وSHA-256
/join "parts/manifest.json" [اسم الناتج]
/upload                              # جمع ملفات قبل نقلها؛ يدعم المستندات والفيديو والصوت والصور
/upload_done                         # طلب الوصف والملاحظة
/skip                                # تخطي حقل اختياري
/upload_confirm                      # تأكيد الحفظ على Drive
/cancel_upload                       # إلغاء الجلسة
/jobs
/cancel <معرف العملية>
/status
```

`/download` دون وسيطة يفتح متصفح Drive بأزرار تنقل وصفحات واختيار متعدد؛ بعد اختيار الملفات أرسل `/download_done` لإرسالها بالتتابع، أو `/cancel_download` لإلغاء الاختيار. ويمكن استخدام `/download "مسار"` للتنزيل المباشر. اختيار الملفات يتم برموز داخلية عشوائية مرتبطة بمستخدم Telegram، لا بأسماء الملفات داخل بيانات callback. الملفات والمجلدات تُرسل إلى المحادثة التي بدأت العملية. مجلد Drive يُنشأ له ZIP محلي مؤقتًا بعد فحص تقريبي للمساحة. إذا تجاوز الملف الحد المحلي المحافظ البالغ 2,000,000,000 بايت، يُقسم على القرص ويُرسل كل جزء و`manifest.json`؛ تُترك الأجزاء في TEMP لإتاحة الاستعادة.

`/mv` يعيد تسمية عنصر Drive في مجلده نفسه ولا يستبدل عنصرًا موجودًا. استخدم علامات اقتباس حول المسارات والأسماء ذات المسافات. `/move` ينقل ملفًا أو مجلدًا إلى مجلد موجود، مع رفض النقل إلى الذات أو إلى مجلد فرعي. `/cp` ينسخ الملفات فقط عبر القراءة والكتابة المتدفقة. `/rm` يحذف ملفًا أو مجلدًا فارغًا بعد تأكيد؛ لا يحذف مجلدات غير فارغة ولا يوفر حذفًا نهائيًا عبر Drive API.

يعرض التنزيل شريط تقدم يُحدّث رسالة واحدة، ويقيس بايتات الملف التي تمررها طبقة الإرسال إلى طلب Local Bot API؛ السرعة والوقت المتبقي تقديريان وليسا إقرارًا من Telegram باستلام الملف حتى ينجح طلب الإرسال. ويعرض رفع الملفات الواردة من Telegram شريطًا مشابهًا أثناء استقبالها ونسخها إلى Drive، مع النسبة والحجم والسرعة والوقت المتبقي التقريبي؛ تُحدد فترة التحديث عبر `PROGRESS_UPDATE_INTERVAL`. تنشأ ZIP وتُقرأ الملفات في خيوط خلفية لتجنب حجب حلقة asyncio. يبدأ `/upload` جلسة خاصة بالمستخدم ويعرض متصفحًا لاختيار مجلد الحفظ، ويمكن تغيير الوجهة بزر «اختر هذا المجلد للرفع». يدعم الجمع الفيديو المرسل كفيديو عادي، إضافة إلى المستندات والصوت والصور، ويؤكد البوت إضافة كل ملف برسالة وعدّاد. بعد التجميع تظهر أزرار إنهاء الجمع والتخطي والتأكيد والإضافة والإلغاء، ولا يبدأ النسخ إلى Drive إلا بعد «تأكيد ورفع إلى Drive». إذا ظهر «لا توجد ملفات مجمعة»، فابدأ `/upload` أولًا وانتظر رسالة «أُضيف ... إلى دفعتك» قبل إنهاء الجمع. الملفات الفاشلة تبقى لإعادة المحاولة ما دامت جلسة Colab مستمرة. الرفع المباشر خارج الجلسة يقبل caption بصيغة `الوصف: ...` و`ملاحظة: ...`. يُحفظ journal الوظائف تحت مجلد مخفي في جذر Drive عند توفر mount، ويعود عند بدء البرنامج؛ العمليات التي كانت قيد التشغيل تتحول إلى `needs_recovery` وتحتاج تحققًا يدويًا من الوجهة، ولا يعاد تشغيلها تلقائيًا. جلسات اختيار الملفات والرفع المرحلية تبقى محلية ولا تستعاد بعد انتهاء Colab. إدارة صلاحيات المشاركة مستبعدة وفق نطاق التنفيذ الحالي.

لتقسيم ملف وإعادة تجميعه برمجيًا، توفر `transfer.chunking.split_file` و`join_parts` ملف manifest مع SHA-256 لكل جزء وللملف. يستخدم أمر التنزيل هذا المكون تلقائيًا عند تجاوز الحد.

## CSV

يكتب `CsvIndex` ملف `_drive_telegram_index.csv` بسجل مستقل لكل ملف وأعمدة ثابتة تشمل المجموعة والمسار والوصف والملاحظة وSHA-256 والحالة. يكتب نسخة مرحلية ويحفظ نسخة `.bak` للاسترجاع. استبدال الملفات على Drive Mount قد لا يكون ذريًا كليًا في كل الحالات. منع التكرار الحالي قائم على المسار والحجم؛ عند تطابقهما يعتبره سجلًا سابقًا. لا يُفهرس ملف CSV نفسه تلقائيًا.

## الصلاحيات

إدارة صلاحيات مشاركة Google Drive مستبعدة من هذا الإصدار، ولا توجد لها أوامر Telegram. عمليات الملفات تعمل ضمن صلاحيات الحساب الذي رُكّب Drive له في Colab؛ تغيير صلاحيات المشاركة نفسها ليس جزءًا من التنفيذ.

## المساحة والأمان

لا تُحمّل الملفات داخل RAM دفعة واحدة؛ النسخ والتقسيم يقرآن كتلًا من القرص. لكن استقبال ملف Telegram محليًا يحتاج مساحة كافية على مساحة عمل الخادم، ونقل/نسخ Drive Mount قد يستلزم وجود المصدر والوجهة معًا. لا يمسح المشروع ملفات أخرى لتوفير المساحة. اجعل مجلد بيانات خادم Bot API على مساحة مناسبة، إذ قد يحوي بيانات تنزيل محلية. جلسات Colab مؤقتة؛ الملفات تحت `/content` قد تختفي، ولا توجد استعادة مضمونة لها. لا تتجاوز سياسات إبقاء الجلسة مفتوحة.
