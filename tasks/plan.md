# خطة إصلاح رفع الفيديو وتحسين واجهة البوت

## الهدف
إصلاح جلسة `/upload` بحيث تستقبل الفيديو المرسل كرسالة Telegram `video`، وليس المستندات فقط، ثم تحسين قابلية الاستخدام بأزرار ورسائل واضحة خلال اختيار الوجهة، جمع الملفات، إدخال البيانات الوصفية، والتأكيد.

## التشخيص
- المعالج الحالي يستخدم `@router.message(F.document)` فقط.
- Telegram يرسل الفيديو العادي في الحقل `message.video`، لذلك لا تُضاف الفيديوهات إلى `_UPLOAD_SESSIONS`.
- زر اختيار مجلد الرفع موجود داخل المتصفح، لكن بقية خطوات الرفع تعتمد على أوامر نصية، ما يسبب التباسًا بعد كل إجراء.

## قرارات التصميم
- توحيد استقبال `document` و`video` و`audio` و`photo` في معالج واحد، مع استخراج file_id/name/size/file_unique_id بأمان.
- إبقاء الملفات المؤقتة محليًا أثناء الجمع، وعدم نسخها إلى Drive قبل زر التأكيد.
- إضافة callbacks قصيرة خاصة بجلسة الرفع: إنهاء الجمع، إلغاء الجلسة، عرض المتصفح، التخطي، والتأكيد.
- جعل الأزرار مساعدة لا بديلًا عن الأوامر، للحفاظ على التوافق مع الاستخدام النصي.
- معالجة زر callback القديم/المنتهي برسالة واضحة بدل الفشل الصامت.

## مراحل التنفيذ
1. إضافة أدوات لوحة أزرار الرفع واستخراج بيانات الوسائط.
2. تحويل معالج استقبال المستند إلى معالج وسائط يدعم الفيديو.
3. إضافة أزرار callbacks لكل مرحلة وتحديث الرسائل الإرشادية والملخص والنتيجة.
4. إضافة اختبارات unit لمسار الفيديو والأزرار والحالات غير الصالحة.
5. تشغيل الاختبارات وruff، وتحديث README بتدفق الاستخدام الجديد.

## معايير القبول
- إرسال فيديو أثناء جلسة `/upload` يضيفه إلى القائمة ويعرض العدد والحجم.
- `/upload_done` والزر المقابل ينتقلان إلى الوصف، ثم الملاحظة، ثم الملخص.
- يمكن إنهاء أو إلغاء أو تغيير الوجهة من الأزرار دون الحاجة لكتابة الأمر.
- `/upload_confirm` والزر المقابل لا يعملان إلا عند وجود دفعة جاهزة.
- الاختبارات وruff يمران دون أخطاء.
